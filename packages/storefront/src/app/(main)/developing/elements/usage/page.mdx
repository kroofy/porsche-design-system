# Native Elements

<TableOfContents headings={['Contract', 'Mapping', 'Forms', 'Appearance', 'Not this family']} />

## Contract

- One native tag, no wrapping host.
- Public `.` export stays the generated custom-element wrapper.
- Native wrappers ship on `./elements`.
- Angular hosts are the native tags.
- Real attributes only. The forced `aria` JSON bag is for custom elements, not for these.
- Vanilla is HTML plus the stylesheet.
- No slotted heading, text, or anchor. Native is always the real tag.
- Stencil custom-element hosts stay until a breaking major.

| `PTagDismissible`                                                                 | `<button class="p-tag-dismissible">`                              |
| `PSpinner`                                                                        | `<svg class="p-spinner">`                                         |
| `PModal`                                                                          | `<dialog class="p-modal">`                                        |
| `PSheet`                                                                          | `<dialog class="p-sheet">`                                        |
| `PInlineNotification`                                                             | `<aside class="p-inline-notification">`                           |

Children stay real tags too. Legend is a `<legend>` inside the fieldset. Accordion summary is a `<summary>`. Modal
header and footer are `<header class="p-modal__header">` and `<footer class="p-modal__footer">`. Inline notification
heading is a real `h1`–`h6`, description is a `<p>`, and dismiss is
`<button class="p-inline-notification__dismiss">`. Select options are `<option>`. Optgroup labels use the native
`label` attribute.

Open a modal or sheet with `showModal()`, not by toggling the `open` attribute. That attribute is modeless.

Native `<select>` optgroups follow UA dropdown styling. They will not match the custom stencil list. `size` or
`multiple` shows groups in-page.

## Forms

The label is a sibling with `for` / `htmlFor`. It is not a slot on the control.

Wrap the field in `.p-field`. Wire description and message with `aria-describedby`. Use `fieldIds` so the ids stay
stable.

<ContentTabs label="Labeled field by framework">

<ContentTab label="Vanilla JS">

```html
<div class="p-field">
  <label class="p-label" for="email">Email</label>
  <span class="p-description" id="email-description">Work email</span>
  <input id="email" class="p-input" type="text" name="email" dir="auto" aria-describedby="email-description" />
</div>
```

```js
import { fieldIds, fieldDescribedBy } from '@porsche-design-system/components-js/elements';

const ids = fieldIds();
input.id = ids.control;
label.htmlFor = ids.control;
hint.id = ids.description;
input.setAttribute('aria-describedby', fieldDescribedBy(ids, { description: true }));
```

</ContentTab>

<ContentTab label="React">

```tsx
import { fieldDescribedBy, PInputText, PLabel, useFieldIds } from '@porsche-design-system/components-react/elements';

export const EmailField = () => {

  return (
    <div className="p-field">
      <PLabel htmlFor={ids.control} required>
        Email
      </PLabel>
      <span className="p-description" id={ids.description}>
        Work email
      </span>
      <PInputText id={ids.control} name="email" aria-describedby={fieldDescribedBy(ids, { description: true })} />
    </div>
  );
};
```

```ts
import { Component } from '@angular/core';
import { fieldIds, fieldDescribedBy, PInputText, PLabel } from '@porsche-design-system/components-angular/elements';

@Component({
  selector: 'app-email-field',
  standalone: true,
  imports: [PLabel, PInputText],

    <div class="p-field">
      <label pLabel [attr.for]="ids.control" required>Email</label>
      <span class="p-description" [id]="ids.description">Work email</span>
      <input pInputText [id]="ids.control" name="email" [attr.aria-describedby]="describedBy" />
    </div>
  `,
})
export class EmailField {
  readonly ids = fieldIds();
  readonly describedBy = fieldDescribedBy(this.ids, { description: true });
}
```

Error and success sit on the control as `data-p-state` plus `aria-invalid` when needed. The message is a sibling
`.p-message`. Required is a `*` inside the label (`PLabel required` or `.p-label__required`), not a slot.

Loading is native `disabled` + `aria-busy` + `data-p-loading`. There is no fake overlay host.

## Appearance

PDS-only look goes on `data-p-*`. Native behaviour stays on native attributes.

| Look        | How                                                            |
| ----------- | -------------------------------------------------------------- |
| Variant     | `data-p-variant="secondary"`                                   |
| Compact     | `data-p-compact="true"`                                        |
| Hide label  | `data-p-hide-label="true"` on the label                        |
| Field state | `data-p-state="error"` on the control                          |
| Loading     | `data-p-loading="true"` plus native `disabled` and `aria-busy` |

Defaults are omitted. Primary, `compact=false`, and `state="none"` do not write a data attribute.

Public CSS variables still work, for example `--p-spinner-color` and `--p-modal-width`.

## Not this family

These are not 1:1 native tags. Keep the custom-element wrappers:

- Switch
- Button tile / link tile
- Multi-select (not a native `<select multiple>` skin of the custom dropdown)
- Table sort and scroller
- Accordion summary-before / summary-after and the deprecated heading API
- Model-signature overlay-as-mask
- Modal stuck-footer frost

Do not start a Mitosis rewrite from this export. Do not swap the public `.` CE export to native.
